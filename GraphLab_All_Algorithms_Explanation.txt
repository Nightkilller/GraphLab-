GRAPHLAB: COMPLETE ALGORITHMS EXPLANATION GUIDE

This document explains the core algorithms implemented in GraphLab, including their mathematical purpose, time complexity, and step-by-step execution logic.


1. GRAPH ISOMORPHISM ALGORITHM (G₁ ≅ G₂)

• Purpose: Determines whether two distinct graphs share the exact same connection topology despite having different vertex labels or visual positions.
• Time Complexity: O(|V|!) worst case; O(|V| + |E|) average case with pruning.
• Step-by-Step Logic:
  1. Invariant Pre-filtering: Instantly checks necessary structural properties:
     - Number of vertices must match: |V(G₁)| == |V(G₂)|.
     - Number of edges must match: |E(G₁)| == |E(G₂)|.
     - Sorted degree sequences must be identical.
     If any invariant fails, the algorithm halts immediately with a non-isomorphic proof.
  2. Backtracking Bijection Search: If invariants pass, the algorithm systematically pairs an unassigned vertex u ∈ G₁ with a candidate v ∈ G₂ that shares the exact same degree.
  3. Adjacency Consistency Check: For each new pairing, it verifies that adjacency between already mapped vertices in G₁ is perfectly preserved in G₂.
  4. Termination: If a complete bijection π: V(G₁) → V(G₂) is found, it returns the mapping table; otherwise, it proves no structure-preserving mapping exists.


2. HAVEL-HAKIMI DEGREE SEQUENCE ALGORITHM

• Purpose: Tests if a given finite list of non-negative integers can represent the degree sequence of a simple undirected graph (Graphicality Test).
• Time Complexity: O(n² log n), where n is the number of vertices.
• Step-by-Step Logic:
  1. Sort the list of degrees in descending order: [d₁, d₂, d₃, ..., dₙ].
  2. Remove the first (largest) element d₁.
  3. Subtract 1 from each of the next d₁ elements in the list.
  4. If any number becomes negative, the sequence is impossible (Non-Graphical).
  5. Repeat steps 1–3 until all numbers become 0 (Graphical) or a negative value appears.
  6. Realization Construction: GraphLab connects vertices based on these reduction steps to draw a valid graph on canvas.


3. BIPARTITE 2-COLORING ALGORITHM

• Purpose: Checks if graph vertices can be partitioned into two independent sets such that no two adjacent vertices share the same color (Equivalently: contains no odd-length cycles).
• Time Complexity: O(|V| + |E|).
• Step-by-Step Logic:
  1. Initialize all vertices as unvisited (no color assigned).
  2. Pick an unvisited vertex, assign it Color 1 (Red), and traverse its neighbors.
  3. For the current vertex u, examine all its neighbors v:
     - If v is uncolored, assign it the opposite color (Blue).
     - If v already has the same color as u, a conflict is found: the graph contains an odd-length cycle and is NOT bipartite.
  4. Repeat until all components are visited. If no conflict occurs, the graph is Bipartite, and GraphLab partitions them into two vertical columns (V₁ and V₂).


4. COMPLEMENT GRAPH GENERATION ALGORITHM (G')

• Purpose: Constructs the complement graph G' having the exact same vertices as G, but connecting only those pairs of vertices that are NOT connected in G.
• Time Complexity: O(|V|²).
• Step-by-Step Logic:
  1. Read the vertex set V of the original graph G.
  2. For every distinct pair of vertices (u, v) where u < v:
     - If an edge (u, v) exists in G, skip it.
     - If NO edge exists between u and v in G, create an edge (u, v) in G'.
  3. Verifies the fundamental mathematical invariant: |E(G)| + |E(G')| = |V|(|V| - 1) / 2.
  4. Tests self-complementary candidate conditions: |E(G)| == |E(G')| and |V| ≡ 0 or 1 (mod 4).


5. GRAPH MATRIX GENERATION ALGORITHMS (ADJACENCY & INCIDENCE)

• Purpose: Translates graphical network structures into algebraic matrix representations.
• Time Complexity:
  - Adjacency Matrix: O(|V|²).
  - Incidence Matrix: O(|V| · |E|).
• Step-by-Step Logic:
  1. Adjacency Matrix A: Builds an n × n matrix where row i and column j represent vertices vᵢ and vⱼ. If an edge exists between them, A[i][j] = edge weight (or 1 for unweighted); otherwise A[i][j] = 0.
  2. Incidence Matrix B: Builds an n × m matrix where rows represent n vertices and columns represent m edges:
     - For undirected graphs: B[i][e] = 1 if vertex i is an endpoint of edge e; 0 otherwise.
     - For directed graphs: B[i][e] = -1 if edge e leaves vertex i (source); +1 if edge e enters vertex i (target).


6. DIJKSTRA'S SHORTEST PATH ALGORITHM

• Purpose: Finds the shortest path from a single starting vertex to all other vertices in a weighted graph with non-negative edge weights.
• Time Complexity: O((|V| + |E|) log |V|) using a Min-Priority Queue.
• Step-by-Step Logic:
  1. Initialize distance to start node as 0 and all other vertices as infinity (∞).
  2. Insert the start node into a Min-Priority Queue with distance 0.
  3. Extract the node u with the smallest tentative distance from the priority queue.
  4. For each neighbor v of u:
     - Calculate new distance: newDist = dist[u] + weight(u, v).
     - If newDist < dist[v], update dist[v] = newDist and set parent[v] = u.
     - Push or update v in the priority queue.
  5. Repeat until the queue is empty. Reconstruct shortest paths by following parent pointers.


7. BELLMAN-FORD SHORTEST PATH ALGORITHM

• Purpose: Computes shortest paths from a single source vertex and supports graphs containing negative edge weights; detects negative-weight cycles.
• Time Complexity: O(|V| · |E|).
• Step-by-Step Logic:
  1. Set dist[start] = 0 and dist[v] = ∞ for all other vertices.
  2. Relax all edges |V| - 1 times:
     - For every edge (u, v) with weight w:
       If dist[u] + w < dist[v], update dist[v] = dist[u] + w and parent[v] = u.
  3. Negative Cycle Check (Pass |V|):
     - Iterate through all edges one more time.
     - If any edge can still be relaxed (dist[u] + w < dist[v]), a negative cycle exists and shortest paths are undefined.


8. TECHNOLOGIES, TOOLS & DATA STRUCTURES USED IN THIS PROJECT

• Programming Languages & Core Web Technologies:
  - TypeScript: Provides static typing, strong interfaces for graph nodes, edges, matrices, and algorithm inputs/outputs, eliminating runtime type errors.
  - HTML5 & CSS3: Uses HTML5 Canvas API, SVG vector elements, and modern CSS custom variables for seamless theme switching.
  - JavaScript (ES Modules): Modern modular syntax with generator functions (function*) to enable step-by-step algorithm playback.

• Frontend Framework & Libraries:
  - React 19: Component-based user interface architecture with optimized hooks, memoization, and error boundaries.
  - Vite 6: Next-generation build tool and development server providing instant Hot Module Replacement (HMR) and optimized production bundling.
  - Tailwind CSS v4: Utility-first styling system used for modern, responsive UI design across desktop, tablet, and mobile devices.
  - Radix UI Primitives: Unstyled, fully accessible UI components including Popovers, Tabs, Dropdown Menus, Sliders, and Tooltips.
  - Lucide React: Clean, modern vector icon set for tools, algorithm indicators, and modal navigation.
  - Sonner: High-performance toast notification library for instant user feedback.

• State Management:
  - Zustand 5: Centralized, lightweight state management store managing graph nodes, edge maps, selection states, undo/redo history stacks, and visualization step cursors with zero unnecessary re-renders.

• Rendering & Visualization Engines:
  - Vector SVG Engine: Renders pixel-perfect nodes, edges, directional arrowheads, and quadratic Bezier curves for directed connections.
  - HTML5 Canvas Engine: High-performance 2D rendering mode for fluid interaction.
  - Three.js & React Three Fiber (@react-three/fiber, @react-three/drei): Full 3D WebGL rendering mode allowing 3D spatial rotation, zoom, and orbit controls for graphs.

• Core Data Structures Implemented:
  - Adjacency List: Map<number, GraphEdge[]> storing edges for efficient graph traversal and neighborhood inspection.
  - 2D Matrices: Array<Array<number>> representing Adjacency Matrix (A) and Incidence Matrix (B).
  - Min-Priority Queue / Heap: Implemented for greedy minimum-distance extraction in Dijkstra's algorithm.
  - Undo/Redo Stacks: History tracking stacks storing graph mutation states for multi-level undo and redo operations.
  - Hash Sets & Hash Maps: Constant-time O(1) lookups for tracking visited vertices, bijection mapping tables, and cycle detection.

• Testing, Verification & Offline Support:
  - Vitest: Fast unit testing framework verifying algorithm correctness, invariants, and graph transformations.
  - Vite Plugin PWA & Service Workers: Enables Progressive Web App (PWA) caching for 100% offline-first execution directly from a local browser or pen drive with zero internet access required.
